The dashboard labels `~z-ai/glm-flash-latest` as Custom, so `/custom-openai/v1` is the documented custom route to target that configured endpoint. The same docs also say requests are routed by model ID and model IDs can work on compatible routes; this is provider behavior, not evidence that the earlier failure was caused by either endpoint. The historical trace `trace_b2226419b2064ec9ad3b407b0a63380f` records only `APIConnectionError` / “Error getting response”; its exception chain was not saved, so the exact cause of that earlier POST remains unrecoverable.
